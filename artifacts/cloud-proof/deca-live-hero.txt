## Credentials this needed

| Variable | Value in this run |
|---|---|
| `DECA_AGENT_API_BASE_URL` | `https://api.genlabs.dev` |
| `DECA_SESSION_ID` | the web session id supplied in chat |
| `DECA_GIT_TOKEN` | the existing GitHub token, so the agent could push |

The model key was not configured anywhere: Star enrolls a short-lived
`deca_oc_` key from the session id and sends it to the runner inside the
session config frame, so the runner calls the same gateway the user's own
chat does.

## Friction found while doing this

* Toggling `/cloud` opens the command palette and the first automated
  keystrokes landed in its filter; a person just presses Enter and
  types, so this is a driver problem, not a product one. Fixed in the
  driver by dismissing the palette with Esc.
* The screenshot could not come back **inside** the conversation: the
  cloud agent's ACP frames carry text and tool calls only, so
  `cloudTurn.apply` drops image content blocks. The image above was
  recovered from the branch the agent pushed. Getting the agent to hand
  the picture straight into the chat is the next real step.
* The driver's stop heuristic waits for a quiet screen, so it reported
  5m20s of wall time for a 2m16s turn. The turn time above comes from
  the transcript and from the TUI footer, not the driver clock.

Prompt, in full and with no other instructions:

Session `45f30934-ab90-41c3-a0c9-e55e7bf579ae`, workflow run

What it did on its own:

```
 +18s bash  pwd && ls -la                      -> /tmp/agent-workspace, empty
 +18s ls    /tmp/agent-workspace
 +20s bash  which chromium chromium-browser google-chrome node npm python3
 +22s bash  curl fonts.googleapis.com          -> 200

 +37s bash  chromium --headless ... --window-size=1440,900 --screenshot=hero-desktop.png

 +62s ERROR turn failed
```

The turn died on the agent's own attempt to show the picture:

```
failed to read: websocket: message too big: read limited at 32769 bytes
```

Root cause: `Client.relayTurn` dials the relay with `websocket.Dial`
and never raises the read limit; nothing under `internal/cloud/` calls
`SetReadLimit` (`grep -rn "SetReadLimit" internal/` returns no hit in
the cloud client). coder/websocket caps frames at 32 KiB by default, so
the first frame carrying an image kills the turn before any ACP
decoding happens. Text-only turns never get near the cap, which is why
the first run looked fine.

Two things this run shows:

* Without hand-holding the agent still built and rendered the page, and
  it went looking for the screenshot to show me - the intent is there.
* It did not know about a repo: no clone, no commit, no push, because
  nothing asked it to publish. On an ephemeral runner that work is gone
  when the runner idles out, so "show me the design" cannot be satisfied
  until images can come back in-band.

Session terminated after the turn: `DELETE ... -> 200`.
